# 論文理解・講義ノート PDF 制作ガイド

## 適用範囲

この `AGENTS.md` は `paper-lecture-notes/` ディレクトリとその配下にだけ適用する。書籍翻訳や体系的数学教科書の制作へ、このディレクトリ固有の論文読解ルールをそのまま適用しない。上位の指示と衝突する場合は上位の指示を優先し、判断できない場合は確認する。

## 目的

論文を自分で説明・検証できる水準まで咀嚼し、主張、仮定、定義、手法、証明・導出、実験、限界、関連研究を教育的な順序に再構成した講義ノート形式の PDF を作る。原論文の記述、執筆者の解釈、外部知識、未解決の疑問を明確に区別し、各説明を原論文または追加出典まで追跡可能にする。

## 想定成果物

- 前提知識、学習目標、本文、節末要約、演習または確認問題を備えた講義ノート PDF
- 再現可能な編集ソースとビルド手順
- 論文および外部資料の書誌・権利・参照台帳
- 主張、式、図表、実験結果と原論文のページ・番号を結ぶ追跡表
- 仮定・定義・主張・証明・実験・限界・疑問の分析記録
- 再計算、小例、反例、実装・再現試行等の理解検証記録

ノートは原論文の単なる和訳や節順の写しではなく、理解のための再構成物とする。ただし再構成によって原論文の主張範囲を変えない。

## 推奨ディレクトリ・ファイル構成

既存プロジェクトでは既存構成を優先する。新規案件では、次を参考に構成案を提示し、確認後に採用する。名前と階層は固定ではない。

```text
<project>/
  sources/             # 原論文・補助資料。公開成果物と分離
  bibliography.*       # 書誌、Paper ID、版、URL、参照日、権利
  planning/            # 読解範囲、読者、学習目標、構成案
  analysis/            # 主張分解、仮定、導出、実験、疑問
  traceability.*       # ノートから式・図表・ページへの対応
  manuscript/          # 講義ノートの編集ソース
  exercises/           # 問題、ヒント、解答方針
  assets/              # 図表。引用・再描画・新規作成を区別
  calculations/        # 再計算、小例、反例、再現用コード等
  build/               # 一時生成物
  dist/                # 配布候補 PDF
  qa/                  # ビルド・引用・内容検証の記録
```

原論文、編集ソース、計算用作業ファイル、ビルド中間物、最終 PDF を不用意に混在させない。データやコードに秘密情報・利用制約がある場合はリポジトリ外保管も含めて扱いを文書化する。

## ツールチェーンの決定

- LaTeX、Typst、Pandoc その他の方式を、この指示だけで生成・固定しない。
- 既存案件では既存のビルド方式、設定、命名、引用管理、依存管理を優先する。
- 新規案件では、数式、参考文献、相互参照、コード・図表、再現性、日本語組版の要件に基づく候補を提案し、確認後に最小構成を作る。
- 合意前に大規模なテンプレートや依存を導入しない。

## 標準ワークフロー

1. **スコープ確認**: 対象論文と版、目的、想定読者、前提知識、扱う範囲、必要な深さ、公開範囲、既存ツールチェーンを確認する。
2. **資料登録**: 原論文に Paper ID を付け、著者、題名、掲載先、年、DOI/URL、版・改訂、ページ方式、権利、参照日を記録する。補助資料にも別 ID を付ける。
3. **一次読解**: 問題設定、主要主張、前提、定義、手法、証明・導出、実験、限界、関連研究、著者が述べる未解決点を分解する。
4. **追跡表作成**: ノートで扱う項目を、原論文の節、ページ、式番号、定理番号、図表番号、付録へ対応させる。
5. **理解検証**: 導出の途中式、次元・極限・境界条件、簡単な数値例、特殊例、反例、実験条件を検討する。可能なら独立に再計算または小規模再現する。
6. **講義設計**: 学習目標と前提知識を先に示し、理解に必要な順へ再構成する。動機、直観、定義、主張、導出、例、限界、節末要約、演習を配置する。
7. **執筆**: 記述の種別と出典を示し、解釈や外部知識を原論文の主張に見せない。不確かな点は疑問として残す。
8. **内容レビュー**: 引用精度、主張の強さ、仮定の保持、式・図表対応、理解検証、演習の解答可能性を確認する。
9. **ビルドと PDF 検証**: クリーンな状態から生成し、ログと全ページの表示を確認する。

## 論文の分解規約

- **問題設定**: 何を解決し、何を対象外とするかを記録する。
- **主張**: 結論の種類、適用範囲、条件、比較対象、著者が示す根拠を対にする。
- **仮定**: 明示仮定と暗黙に必要と思われる仮定を分ける。後者は「解釈」または「要確認」と表示する。
- **定義**: 原論文の定義、一般的な別定義、ノート内の便宜的規約を区別する。
- **手法**: 入力、処理、出力、設計選択、比較手法、計算量または実施条件を分解する。
- **証明・導出**: 前提、使用結果、変形の根拠、結論までの流れを復元し、省略箇所を推測で確定しない。
- **実験**: データ、分割、前処理、ベースライン、指標、ハイパーパラメータ、乱数、統計処理、アブレーション、再現条件を可能な範囲で整理する。
- **限界**: 著者が述べる限界と、ノート執筆者が考える追加の限界を分ける。
- **関連研究**: 原論文による位置付けと、外部調査による補足を分け、引用元を付ける。

## 記述種別と執筆規約

本文またはノート体系で、少なくとも次の種別を識別可能にする。

- **原論文**: 原論文に明記された主張・定義・結果。ページ、節、番号等を付ける。
- **解釈**: 原論文から執筆者が読み取った意味、直観、含意。断定の強さを根拠に合わせる。
- **外部知識**: 教科書、別論文、公式資料等から補った背景。独立した出典を付ける。
- **未解決の疑問**: 根拠不足、曖昧さ、再現不能、理解未了の点。推測で解消しない。
- **AI 生成の補足**: 候補説明、例、導出等は検証状態を表示し、出典または独立検証なしに確定本文へ入れない。

論文にない主張を、その論文の結論として書いてはならない。相関を因果へ、限定条件付き結果を一般結果へ、実験上の観察を証明済み命題へ拡張しない。否定的結果、不確実性、信頼区間、評価条件を省略して結論を強めない。

文体、句読点、用語、略語、原語併記、数値・単位、引用形式をプロジェクト内で統一する。直接引用と要約を区別し、要約でも出典を示す。

## 講義ノートとしての構成

- 冒頭に対象読者、前提知識、学習目標、論文の位置付け、読み終えた後に説明できる事項を示す。
- 必要な背景を、原論文の新規性と混同しない形で先に説明する。
- 節ごとに「なぜ必要か」を示し、定義、直観、形式的説明、例、論文内での役割を接続する。
- 各主要節に節末要約を置き、主張、仮定、分かったこと、残る疑問を短く整理する。
- 演習または確認問題を設け、単なる本文抜き書きだけでなく、定義確認、導出、特殊例、反例、実験解釈を含める。
- 問題には依存節と、必要に応じて難度、ヒント、解答または解答方針を付ける。本文だけから解けない場合は追加資料を示す。

## 追跡可能性と理解検証

- 原論文由来の主張、式、定義、数値、図表には、Paper ID とページ、節、式・定理・図表番号等を付ける。
- 版によってページや番号が異なる場合は版を明記し、識別可能な代替位置情報を加える。
- ノートで式を変形・改番した場合は、元の式番号と変形内容を記録する。原論文と同じ番号に見せて異なる式を置かない。
- 導出は次元、符号、境界値、極限、簡単な入力、既知の特殊例で検算する。
- 主張の必要条件を外した反例、適用範囲外の例、極端なケースを検討し、主張の境界を理解する。
- 実験値を再計算できる場合は計算式と丸めを確認する。再現不能なら不足情報と試行条件を記録する。
- 理解できていない箇所を滑らかな文章で隠さず、未解決の疑問として位置と次の確認方法を残す。

## 出典・引用・著作権

- 原論文と外部資料の書誌、版、DOI/URL、ページ、参照日、ライセンス・利用条件を記録する。
- 直接引用は必要な長さに留め、引用範囲と出典を明確にする。要約や翻訳も原典を示す。
- 孫引きを避ける。原典未確認の場合は、二次資料経由であることを明示する。
- 図表、付録データ、コード、スクリーンショットは本文とは別の利用条件を確認する。
- 公開・配布前に、引用、図表の再利用・改変、データ、コード、ライセンス表示を確認する。
- 秘密情報、非公開査読資料、個人情報、契約で制限されたデータ、権利不明素材をコミットしない。

## 数式・記号

- 記号は初出で定義し、型、次元、定義域、添字範囲、確率変数か実現値か等を必要に応じて示す。
- 原論文とノートで記号を変える場合は対応表と理由を示す。複数資料の記号を無言で混ぜない。
- 式変形では使用した仮定、定理、近似、極限操作を明記する。近似と等号を混同しない。
- 式番号、本文参照、演算子、ベクトル・行列・集合の書体を統一し、PDF 上で欠落や崩れを確認する。

## 図表

- 図表ごとに出典、元番号、ページ、扱い（引用・再描画・改変・新規作成）と権利状態を記録する。
- 原論文の図表を再描画した場合は、値、軸、単位、凡例、集計条件が原図と一致するかを照合し、再描画であることを示す。
- 解釈を助ける新規図は、原論文の結果そのものと誤認させず、作成根拠・データ・条件を示す。
- 図表番号、キャプション、本文参照を一致させ、色覚、白黒印刷、縮小表示でも意味が伝わるようにする。

## PDF ビルド

- ビルド手順、依存、入口ファイル、出力先を文書化し、生成物と中間物を本文ソースから分離する。
- ビルド成功だけを完了条件にしない。エラーと警告、未解決参照、重複ラベル、欠落引用、参考文献、目次、しおり、式・図表番号を確認する。
- 日本語、欧文、数式、コードのフォント埋め込み、文字化け、行送り、禁則、長い URL、脚注、余白、ページ番号、はみ出しを確認する。
- 全ページを目視または画像化して確認し、章節境界、図表位置、キャプション、数式改行、空白ページ、リンク、画像解像度を検査する。

## 品質検証

- 学習目標、前提知識、節末要約、演習または確認問題が揃い、講義ノートとして読める。
- 主要な主張ごとに仮定、根拠、適用範囲、限界が対応している。
- 原論文、解釈、外部知識、未解決の疑問、AI 生成補足が識別できる。
- 式・図表・ページへの追跡表に欠落や誤対応がなく、引用文と数値を原資料と照合済みである。
- 少なくとも重要な導出・主張について、再計算、小例、特殊例、反例、再現試行等の妥当な理解検証が記録されている。
- PDF の警告、参照、目次、参考文献、数式、フォント、ページ崩れを確認し、実施日・対象・結果・残件を記録している。
- Git 差分を確認し、原資料、中間物、秘密情報、権利不明素材、無関係な変更を含めていない。

## 禁止事項

- 論文にない主張を論文の結論として書くこと、または主張から条件・不確実性・限界を落として強く見せること。
- 原論文の内容、執筆者の解釈、外部知識、疑問、AI 生成補足を無表示で混ぜること。
- 式、図表、実験値、引用を、版・ページ・番号等へ追跡できないまま転載・変形すること。
- 理解できない導出や不足情報を推測で埋め、検証済みとして扱うこと。
- 権利不明の論文、図表、データ、コード、非公開情報、秘密情報をコミット・公開すること。
- 合意なくツールチェーンを固定・置換すること、またはビルド成功だけで完成扱いすること。

## 完了条件

- 合意した読者・範囲に対し、前提知識、学習目標、教育的本文、節末要約、演習または確認問題を備えた PDF が完成している。
- 主張、仮定、定義、手法、証明・導出、実験、限界、関連研究が必要な深さで分解・再構成されている。
- 原論文、解釈、外部知識、未解決の疑問が区別され、主要内容をページ・式・図表番号等まで追跡できる。
- 引用精度と理解検証が確認済みで、未解決事項と再現上の制約が明示されている。
- 合意した手順で PDF を再生成でき、警告、参照、目次、数式、フォント、全ページのレイアウト検証を通過している。
- 配布物に秘密情報や権利不明素材がなく、公開・配布条件が確認されている。
